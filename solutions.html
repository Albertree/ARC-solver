목표: Pa 에 빠진 grid(출력) 만들기
TASK 에서 막혀(impasse) 한 단계 내려옴 — 강제 아님, 결정 못 해서.

  • grid-count: P0=2, P1=2, Pa=1

  • compare(P0,Pa) = DIFF
  • compare(P1,Pa) = DIFF

[GRID]
목표: 출력 grid 의 {size, color, contents} 정하기
PAIR 에서 막혀 내려옴.
읽은 정보 · 비교
  • P0.G1: size=4x4, colors=[0, 2]
  • P1.G1: size=3x5, colors=[0, 1]
  • compare(P0.G1,P1.G1) = DIFF, COMM=[]
판단: 막힘 → 더 깊이 내려감  (부분 COMM (같음=[]) — 출력이 입력에 의존 → OBJECT 로)
[OBJECT]
목표: 출력 객체의 {위치, 색} 정하기 — 위치=COMM, 색=G0 에서
GRID 에서 막혀 내려옴. 여기서 property 별 우선순위 탐색.
읽은 정보 · 비교
  • P0: G0(색 2 @[1, 1] grid 4x4) → G1(색 2 @[3, 3] grid 4x4)
  • P1: G0(색 1 @[1, 4] grid 3x5) → G1(색 1 @[2, 4] grid 3x5)
  • anti-unify schema: color=from_g0, coordinate=coord, grid_size=from_g0
property 탐색 (우선순위대로, 첫 적합 채택)
▶ color
  • ✓ 채택 from_g0 (출력 = 같은 pair 입력) — 모든 pair 에서 출력=입력 (보존)
▶ coordinate
  • ✗ in_coord + Δ (입력 위치 기준 = from_g0/이동) — pair 마다 (출력−입력) offset 이 달라 불일치
  • ✗ const (모든 출력 동일) — 출력 위치 제각각 [[3, 3], [2, 4]]
  • ✓ 채택 grid_dims + Δ (grid 크기 기준 = 모서리 등, cross-property) — (출력−(grid_h,grid_w)) = [-1, -1] 로 일관 → 모서리류
▶ grid_size
  • ✓ 채택 from_g0 (출력 = 같은 pair 입력) — 모든 pair 에서 출력=입력 (보존)
판단: 결정적 → 멈춤  (schema 전부 설명됨)
