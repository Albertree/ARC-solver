# [2026_0425] run.py 로깅 개선 및 WM 출력 포맷 변경

`dev1` 브랜치에서 실행 진입점(`run.py`)과 WM 로거(`agent/wm_logger.py`)를 중심으로 실용적인 개선 작업을 진행했다.

---

## 1. 작업 배경

`main` 브랜치에서 `python run_task.py`를 실행하면 WM 사이클 전 과정이 출력됐는데, `dev1`에서는 `run_task.py`가 삭제되고 `run.py`로 대체되면서 동일한 출력이 나오지 않는 상태였다. 그 원인과 차이를 정리하고, `run.py`가 동등한 기능을 하도록 복원하는 것이 출발점이었다.

---

## 2. 주요 변경 내용

### 2-1. `ActiveSoarAgent.solve()` 복원 — `inject_arc_task` 방식

`dev1`의 `solve()`는 `build_wm_from_task()`를 사용해 goal 구조를 먼저 구성하는 방식이었다. `run_task.py`(main)는 `inject_arc_task()`로 input-link에 task_hex만 주입하고, 이후 elaboration rule이 `^current-task`를 파생시키는 방식이었다.

**변경 전 (`dev1` 기존)**
```python
reset_wm_snapshot()
wm = WorkingMemory()
build_wm_from_task(task, wm)      # goal 구조 포함 전체 세팅
run_cycle(wm, elaborator, proposer, max_steps=self._max_steps, log_wm=self._log_wm)
```

**변경 후 (복원)**
```python
wm = WorkingMemory()
reset_wm_snapshot(wm)             # 초기 WM을 baseline으로 설정

if self._log_wm:
    print_wm_triplets(wm, label="Initial WM (before input)", step=0)

inject_arc_task(task, wm)         # input-link에 task_hex만 주입

if self._log_wm:
    print_wm_triplets(wm, label="After input-link injection (before cycle)", step=0)

out = run_cycle(wm, elaborator, proposer,
                max_steps=self._max_steps, stop_on_goal=True, log_wm=self._log_wm)

if self._log_wm:
    print(f"\n[cycle] {out}")
```

- Initial WM → After injection → 사이클 각 단계 순서대로 WM 상태가 출력된다.
- `run.py`의 `DEFAULT_LOG_WM = True`로 설정해 기본적으로 WM 로그가 켜진다.

### 2-2. `wm_logger.py` — ANSI 색상 → `+`/`-` 기호 방식

기존에는 변경된 WME를 ANSI 배경색(초록/빨강)으로 표시했다. 터미널에서는 보이지만 파일로 저장했을 때 이스케이프 코드가 그대로 노출되는 문제가 있었다.

**변경 전**
```python
# _GREEN_BG / _RED_BG ANSI 코드로 줄 전체를 패딩해서 출력
print(_colorize(text, _GREEN_BG))
print(_colorize(text, _RED_BG))
print(text)
```

**변경 후**
```python
# +/- 기호 + 공백 2칸 prefix, ANSI 없음
print(f"+  {text}")   # 추가/변경된 WME
print(f"-  {text}")   # 제거된 WME
print(f"   {text}")   # 변화 없는 WME
```

- `_GREEN_BG`, `_RED_BG`, `_RESET`, `_colorize()`, `_LINE_WIDTH` 제거
- 로그 파일에서 에디터로 바로 읽을 수 있는 순수 텍스트 diff

출력 예시:
```
══════════════════════════════════════════════════════════════
  [Step 0] After input-link injection (before cycle)
══════════════════════════════════════════════════════════════
   (S1 ^type state
       ^superstate nil
       ^io I1
       ^smem I4
       ^epmem I5)
   (I1 ^input-link I2
       ^output-link I3)
+    (I2 ^task 08ed6ac7)
   (I4 ^id SM1)
   (I5 ^id E1)
══════════════════════════════════════════════════════════════
```

### 2-3. `run.py` — tee 로깅 + 실행 헤더

#### tee 방식 자동 저장

`_Tee` 클래스를 추가해 `sys.stdout`을 래핑, 터미널과 파일에 동시에 출력한다.

| 모드 | 저장 위치 |
|------|-----------|
| train | `run_logs/MMDD_HHMM.log` |
| eval | `eval_result/run_MMDD_HHMM/run.log` |

- `show_task()`의 ANSI 그리드는 tee를 일시 해제해 터미널에만 출력
- train 모드에서 `--out-dir none`으로 저장 끄기 가능

#### 실행 헤더 기록

tee 시작 직후 `_print_run_header()`를 호출해 로그 첫 부분에 재현 정보를 기록한다.

```
==============================================================
  [ARC-solver] 2026-04-26 05:30:17
  cmd  : run.py --task 08ed6ac7
  mode : train
  tasks: 08ed6ac7  (n=1)
  steps: max_steps=50  max_attempts=3
  log  : log_wm=True  quiet=False
==============================================================
```

#### 추가된 기본값 (`DEFAULT_*` 블록)

```python
DEFAULT_LOG_WM    = True          # WM 로그 기본 활성
DEFAULT_TRACE_OUT = None          # --trace-out
DEFAULT_LOG_OUT   = None          # --log-out
DEFAULT_OUT_DIR   = "run_logs"    # --out-dir (none으로 끄기)
```
