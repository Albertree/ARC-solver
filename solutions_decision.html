9/9 정답.

a✓ b✓ c✓ d✓ e✓ f✓ g✓ h✓ i✓

이 문서는 ARBOR 가 easy000a~i 를 SOAR 결정 사이클로 푸는 전 과정을 매 사이클 풀어 적은 해설서다. 새 로직이 아니라, 상태에 따라 불려오는 단위 행동(operator)들의 조합이다.

불변 루프 — 모든 레벨(TASK→PAIR→GRID→OBJECT)에서 같다. 단 *매 단계가 늘 도는 건 아니다* — 상태에 따라 어떤 단위 행동은 생략된다:
관측+목표구체화(frame): 한 노드를 관측 → 그 계층의 property 개수를 알고 목표를 "그 속성들을 찾는다"로 구체화 → [원시(통째) 비교] → (어디가 안 보임=막힘) → 비교 심화(localize) → need → 효과로 DSL 탐색 → 있으면 apply / 없으면 impasse → 하강(holds 가 효과를 변신) → … → 복기(unwind)
예: PAIR 은 원시비교로 '빠진 역할'을 발견하지만, GRID·OBJECT 는 frame 이 속성을 짚어줘 원시(통째)비교를 건너뛰고 곧장 속성별(특정범위·원소고정) 비교로 간다.
편향: COMM=그대로 채택(미지가 공통에 순응) / DIFF=어긋남(같게 or 하강).   자유변수: example=고정(앎) / test 슬롯=만들 것.
깊이 들어가기(하강)impasse→push_substateS1→S2→S3→S4 = TASK→PAIR→GRID→OBJECT
원시 비교compare (통째)COMM/DIFF
비교 심화localize (이름정렬)'어디가' 국소화 → need
범위·원소고정 비교select+compare형제(example 출력) 비교
다름 완화 DSL 찾기find_by_effect효과 매칭(계층 아님)
DSL 조합make_grid + coloring씨앗 원자 조합
SOAR 대응: propose(WM 조건 매칭) → select → apply(WM 변경) → no-change impasse → substate → 복기.

@TASK
cycle 0 · propose=∅ · impasse TASK→PAIR
막힘(no-change impasse) — . 제안할 operator 없음 → substate push TASK→PAIR.
@PAIR
cycle 1 · propose=[compare-pairs] · apply compare-pairs
원시 비교 — 자유변수(test)와 형제(example)의 roles(역할 시그니처) 통째 비교. example=완전(input+output), test=output 빠짐 → verdict = DIFF (다른데 '어디가'는 아직 모름).
@PAIR
cycle 2 · propose=[localize] · apply localize
비교 심화(localize) — roles 를 이름정렬해 항목별 비교 → 빠진 역할 output 으로 국소화. need 생성 → 목표가 날카로워짐:
need = roles.output: False→True requires={'verb': 'add', 'kind': 'roles'} holds=grid
@PAIR
cycle 3 · propose=[search-dsl] · apply search-dsl
DSL 탐색(효과 매칭) — requires={'verb': 'add', 'kind': 'roles'} → 결과 ∅. 이 효과를 내는 DSL 이 없음(roles 를 바꾸는 작용 부재).
@PAIR
cycle 4 · propose=∅ · impasse PAIR→GRID
막힘(no-change impasse) — no activatable DSL @PAIR. 제안할 operator 없음 → substate push PAIR→GRID.
하강이 효과를 변신: holds(grid) → requires(create,grid). GRID 에선 이 효과를 내는 make_grid 가 잡힌다.
@GRID
cycle 5 · propose=[frame-grid, search-dsl] · apply frame-grid
관측 + 목표 구체화 — 만들 대상은 grid 이니, 대표 grid Teasy000a.P0.G0(P0.G0)를 관측한다. grid 의 property 구조(property DSL)는 3가지: size·color·contents. 그래서 목표가 바뀐다 → '이 3속성을 찾아 grid 를 만든다':
goal = grid 의 3속성(size·color·contents)을 찾아 grid 를 만든다
이 단계가 있어야, 다음 비교가 *왜 속성별*인지가 선다. 그리고 3속성을 이미 알기에 — 다음 비교는 grid 통째 *원시비교를 건너뛰고* 곧장 속성별(특정범위·원소고정) 비교로 간다.
@GRID
cycle 6 · propose=[observe-siblings, search-dsl] · apply observe-siblings
특정범위·원소고정 비교 (원시 통째비교는 생략 — frame 으로 3속성을 이미 알기에). 범위 = 자유변수(Pa.output)의 형제 = example 출력들 (원소고정: 역할=output), 이를 property 별로 비교 (편향: COMM→채택):
propertyverdict
sizeCOMM → 채택
colorCOMM → 채택
contentsCOMM → 채택
@GRID
cycle 7 · propose=[search-dsl] · apply search-dsl
DSL 탐색(효과 매칭) — requires={'verb': 'create', 'kind': 'grid'} 를 해소하는 DSL: ['make_grid'] (effect 가 매칭됨).
@GRID
cycle 8 · propose=[compose-grid] · apply compose-grid
DSL 조합 — 결정된 값으로 씨앗 원자 make_grid(캔버스) + coloring(셀)를 조합해 격자를 짓는다 → roles.output 채움 → 목표 achieved.
@PAIR
cycle 8 · propose=∅ · unwind pop → PAIR
복기(unwind) — 하위목표 해소 → substate pop (pop → PAIR). 상위 need 가 채워져 목표 achieved 로 전파 (하강의 거울상).
@TASK
cycle 8 · propose=∅ · unwind pop → TASK
복기(unwind) — 하위목표 해소 → substate pop (pop → TASK). 상위 need 가 채워져 목표 achieved 로 전파 (하강의 거울상).
